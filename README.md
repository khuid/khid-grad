경희대학교 산업디자인학과 졸업전시의 **그해 전시 사이트**를 만드는 저장소입니다.
주소: **https://khid.grad.khu.ac.kr** — 연도마다 `/2026`, `/2027`처럼 뒤에 연도를 붙입니다.

이 문서는 **다음 기수 졸업준비위원회(졸준위) 웹 담당**에게 넘겨주는 안내입니다. 개발을 해 본 적이 없어도 괜찮습니다.
- 여러분이 할 일은 **사이트를 디자인하고, 졸전자들에게서 자료를 받아 오는 것**입니다.
- 코드 작성, 자료 정리·변환, 사이트에 올리기는 **Claude(졸준위 Claude 계정 혹은 기타 AI 툴)가 합니다.** 2026년(35기)도 개발 경험 없는 디자이너 1명이 Claude와 함께 만들었습니다.
- GitHub·Vercel 계정, 학교 도메인은 그대로 물려받으니 **새로 만들거나 학교에 신청할 필요가 없습니다.**

- 지난해에 만든 기능(커밍순 화면, 지도, 이메일 복사 등)은 [FEATURES.md](FEATURES.md)에 정리돼 있습니다. 쓰고 싶은 것만 골라 Claude에게 "이 기능 가져와 줘"라고 하면 됩니다.
- 주소창에 `khid.grad.khu.ac.kr`만 치면 **가장 최신 연도**로 갑니다. 올해 사이트를 공개할 때 이것만 올해로 바꿉니다(Claude가 함).

## 3. 디자인할 것

Figma로 만들고, **데스크톱(1440)과 모바일(390) 두 가지**를 그려 주세요. 태블릿은 둘 사이에서 Claude와 맞춰 갑니다.

| | 무엇 | 비고 |
|---|---|---|
| ☐ | **메인 페이지** | 2026 예: 첫 화면(키비주얼·전시 기간), 전시 기획 글, 전시 안내(장소·지도·지도교수), 졸준위·후원사, 푸터 |
| ☐ | **디자이너 목록** | 졸전자 전원(2026은 55명). 사진 + 국문·영문 이름 |
| ☐ | **디자이너 상세** | 사진, 이름, 연락처(이메일), 포트폴리오 링크, 그 사람의 작품 카드 |
| ☐ | **작품 목록** | 수업별로 나눠 보여 주기(2026은 수업 4개 탭, 작품 74개) |
| ☐ | **작품 상세** | 작품 이미지·영상, 제목, 팀원, 소개글, 링크 |
| ☐ | **링크 미리보기 이미지** | 카톡·인스타에 주소를 보냈을 때 뜨는 썸네일. 1200×630px |
| ☐ | **파비콘** | 브라우저 탭 아이콘. 정사각형 SVG 또는 PNG |
| ☐ | **글꼴** | **웹에 써도 되는 무료/라이선스 글꼴**인지 확인. 한글 글꼴 원본 파일(.woff2·.ttf·.otf)을 Claude에게 전달 |
| ☐ | 커밍순 화면 (선택) | 오픈 전에 주소로 들어오면 보이는 한 장짜리 화면 + 그때용 링크 미리보기 이미지 |

- **빈 상태도 디자인해 주세요.** 포트폴리오 링크가 없는 사람, 작품이 1~2개뿐인 사람, 영상이 없는 작품처럼 자료가 덜 들어온 경우가 꼭 생깁니다. 2026은 개발 중에 하나씩 정했습니다(빈 칸 숨기기, 카드 가운데 정렬 등).
- **긴 글·긴 이름을 넣어 보세요.** 400자 소개글, 두 줄 넘는 작품 제목, 긴 영문 이름에서 레이아웃이 깨지기 쉽습니다.
- 애니메이션·인터랙션은 Figma에 설명을 적거나 참고 영상을 주면 Claude가 만듭니다.

### Figma 파일을 Claude에게 알려 주는 방법
- **링크로 위치를 알려 주세요.** 프레임을 우클릭 → "선택 항목 링크 복사(Copy link to selection)"를 하면 주소에 `node-id`가 붙어요. 이 링크를 주면 Claude가 그 프레임을 바로 찾아요.
- **구역에 번호를 붙여 주세요.** 2026은 메인 페이지 왼쪽에 [1] 히어로, [2] 기획… 같은 라벨을 달고 "[3] 만들어줘"처럼 하나씩 진행했어요.
- **메모는 프레임 옆에 적어 주세요.** 애니메이션, 눌렀을 때 동작, 스크롤 효과처럼 그림으로 안 보이는 건 프레임 오른쪽에 글로 적어 두면 Claude가 같이 읽어요.

### 디자인 파일을 이렇게 만들면 정확해져요
- **데스크톱 1440, 모바일 390 프레임을 따로** 만들어요. 1920처럼 더 큰 화면에서 어떻게 보일지(가운데 정렬인지, 늘어나는지)도 메모해 주세요.
- **오토 레이아웃(Auto Layout)을 쓰면** 간격 값이 정확히 전달돼요.
- **색·글자 스타일을 변수/스타일로 등록**해 두면, Claude가 이름 그대로 코드의 색 규칙으로 옮겨요(2026의 key·deepblue·pale 같은 이름).
- **레이어 이름을 정리해 두세요.** "Frame 123"보다 "작품 카드"가 훨씬 잘 통해요.
- **글꼴 파일은 따로 주세요.** Figma에서는 글꼴 이름만 읽을 수 있어요.
- **로고·키비주얼 같은 그래픽은 SVG나 PNG로 내보내** 주거나, Claude에게 내보내 달라고 하세요.
- **확정된 것과 시안을 구분해 주세요.** 같은 페이지에 버전이 여러 개 있으면 어느 것이 최종인지 프레임 이름에 표시해요.

### 졸전자에게 구글폼으로 받을 것 (2026 실제 규격)

**디자이너 정보 (1인 1회)**

| 항목 | 규격 |
|---|---|
| 이름 | 국문 + 영문. 영문은 **"성 이름" 순서, 이름은 붙여서** (예: Hong Gildong). 폼에 예시를 적어 두면 정리가 쉬움 |
| 이메일 | 필수 |
| 포트폴리오 링크 | 선택, 최대 3개 (인스타그램·비핸스·개인 사이트 등) |
| 프로필 사진 | 2026은 졸준위가 따로 촬영해 같은 구도로 맞춤. 폼으로 받으면 사진마다 구도가 달라짐 |

**작품 (수업별 작품마다, 팀 대표 1명)** — 수업마다 폼을 따로 만들면 정리가 쉽습니다.

| 항목 | 규격 |
|---|---|
| 팀원 이름 | **팀원 전원의 국문 이름을 정확히.** 사이트는 이 이름으로 디자이너와 작품을 잇습니다. 오타·누락이 있으면 그 사람 페이지에 작품이 안 뜸 |
| 작품 제목 | 사이트에 보일 정확한 표기 |
| 소개글 | 국문, **공백 포함 400자 이내.** 2026은 초과 제출이 많았음 → 폼 안내에 글자 수 확인 방법을 적어 두기 |
| 썸네일 | 1장, 세로 4:5 (1080×1350px 권장), JPG, 3MB 이하 |
| 작품 이미지 | 3~7장, 가로 16:9 (1920×1080px 이상), JPG, 장당 5MB 이하, **파일 이름에 순서 번호** (예: `수업_작품명_01`) |
| 영상 (선택) | MP4, 16:9, **15초 이내·10MB 이하.** 더 길거나 소리가 필요하면 유튜브 링크 |
| 링크 (선택) | 최대 3개 (비핸스·유튜브 등) |

- **폼의 응답 시트는 Claude가 읽을 수 있게 "링크가 있는 사람 보기"로 공유**하고, 업로드 파일 폴더는 비공개로 두세요. 파일은 졸준위 계정에서 폴더째 내려받아 Claude에게 주면 됩니다.
- 다시 제출하는 팀이 꼭 생깁니다. 폼에 "수정 제출이면 무엇을 바꿨는지 적어 주세요" 칸을 두면 반영이 빨라집니다.
- 학생 사진·이메일·인스타를 공개 사이트에 올리므로, 폼에 **공개 동의 문구**를 넣어 두세요.

## 7. 유의사항 (꼭 읽어 주세요)

### 하지 말아야 할 것
- **Vercel·도메인 설정을 바꾸지 않습니다.** 학교 도메인은 Vercel 프로젝트 `site-2026`(이름과 달리 **모든 연도의 입구**)에 연결돼 있습니다. 이 프로젝트를 지우거나 도메인을 옮기면 학교 정보처에 다시 요청해야 합니다. 새 연도는 연도 프로젝트(`khid-grad-2027`)만 새로 만듭니다.
- **`2026khid.vercel.app` 주소를 지우지 않습니다.** 2026 인쇄물 QR 코드가 이 주소입니다(학교 도메인으로 넘겨줌).
- **지난 연도 폴더(`2024/`, `2025/`, `2026/`)를 고치거나 지우지 않습니다.** 보안 업데이트만 예외입니다(Claude가 모든 연도에 같이 적용).
- **이 저장소는 공개 저장소입니다.** 비밀번호, 구글 시트 링크, 개인 연락처 같은 건 커밋하지 않습니다.

### 알아 두면 덜 고생하는 것
- **커밋 작성자**: Vercel 무료 요금제는 Vercel 계정에 연결된 GitHub 계정이 만든 커밋만 배포합니다. 다른 이름으로 커밋하면 에러 없이 사이트가 안 바뀝니다. Claude에게 "커밋 작성자는 기존 커밋과 같은 계정으로"라고 알려 주세요.

- **카카오톡 미리보기**: 카카오톡은 링크 미리보기를 한동안 저장해 둡니다. 공개 후에도 예전 이미지가 보이면 [카카오 공유 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 주소를 넣고 캐시를 지우세요.
- **글꼴**: 한글 글꼴은 용량이 커서, 자료가 **다 들어온 뒤** 실제로 쓰는 글자만 남기는 경량화를 한 번 합니다(Claude에게 "폰트 경량화 해줘"). 글꼴 자체에 없는 글자(특수 기호·한자 등)는 기기 기본 글꼴로 보입니다.
- **방문자 통계**: Google Analytics 4가 모든 연도에 자동으로 붙어 있습니다(졸준위 구글 계정으로 analytics.google.com). 작업하느라 들어가는 내 방문을 빼려면 쓰는 브라우저마다 주소 끝에 `?notrack=1`을 붙여 한 번 들어가세요. 보고서는 날짜 범위를 공개일부터로 잡으면 됩니다.
- **이메일 표시**: 2026은 이메일을 누르면 메일 앱이 열리는 대신 주소가 복사되게 했습니다(메일 앱이 없는 PC에서 아무 반응이 없는 문제 방지).
- **카카오톡 안 브라우저**: 많은 사람이 카톡 링크로 들어옵니다. 카톡에서 열었을 때 화면이 덜컹이거나 영상이 안 나오는지 꼭 확인하세요.

## 9. Claude·개발용 메모

여기부터는 Claude(또는 개발 담당)가 작업할 때 보는 부분입니다. 디자이너는 읽지 않아도 됩니다. 작업 규칙 요약은 [CLAUDE.md](CLAUDE.md)에 있습니다.

### 구조

학교 도메인은 작은 **입구**가 받아서 연도별 앱으로 넘겨줍니다. **연도마다 앱(Vercel 프로젝트)이 따로**입니다.

```
방문자 → khid.grad.khu.ac.kr ─ 입구(entry/, Vercel 프로젝트 site-2026)
                                ├ /            → 가장 최신 연도로 이동
                                ├ /2026…       → 2026 앱(2026/, Vercel 프로젝트 khid-grad-2026)
                                ├ /2025…       → 2025 앱(2025/, Vercel 프로젝트 khid-grad-2025)
                                ├ /2024…       → 2024 앱(2024/, Vercel 프로젝트 khid-grad-2024)
                                ├ /2027…       → 2027 앱(2027/, Vercel 프로젝트 khid-grad-2027, 새로 만들 때)
                                └ 그 밖의 주소   → 없는 주소 안내(entry/404.html)
```

한 연도를 고쳐 푸시하면 **그 연도 프로젝트만** 다시 배포됩니다(다른 연도는 그대로). 연도마다 프로그램 버전도 따로입니다.
2024·2025는 2026 이후에 지난 연도로 추가한 사이트입니다(2024는 만료된 아임웹 사이트를 옮김, 2025는 Framer 디자인을 옮김).

### 저장소 모양

| 폴더 | 들어 있는 것 |
|---|---|
| `README.md`, `CLAUDE.md`, `FEATURES.md` | 인수인계 안내(이 문서), Claude용 작업 규칙, 이전 연도 기능 목록 |
| `common/` | 모든 연도가 쓰는 공통 부품 원본 (아래 "공통 규칙") |
| `entry/` | 입구 프로젝트 — 주소 나누기와 없는 주소 안내만 ([entry/README.md](entry/README.md)) |
| `templates/new-year/` | 새 연도 빈 시작 틀 |
| `scripts/` | 공통 도구 (새 연도 만들기, 점검, 공통 부품 복사, 폰트 경량화, 전체 연도 보안 업데이트) |
| `2024/`, `2025/`, `2026/` … | 그 연도 사이트 전부 (코드·데이터·이미지·폰트·그 해 도구) |

이 사이트의 모든 것은 아래 둘 중 하나입니다.

- **공통 규칙**: 매년 똑같이 적용되는 것. 아래 표에 적힌 것만 공통이고, 바꾸면 **모든 연도가 같이 바뀝니다.**
- **연도별**: 그 밖의 전부. 각 연도 폴더 안에만 두고, 다른 연도와 절대 공유하지 않습니다.

> 이전 연도에서 만든 기능 목록은 [FEATURES.md](FEATURES.md)에 있습니다. 공통 규칙이 아니라, 필요할 때 확인하고 가져다 쓰는 기록입니다.
>
> 이 목록에 없는 것은 공통이 아닙니다. "작년에 이렇게 했으니 올해도 그렇겠지" 하고 가져다 쓰지 말고, 필요하면 그 연도 폴더 안에 새로 만드세요.

### 공통 규칙 (모든 연도)

| 무엇 | 어디 | 내용 |
|---|---|---|
| 주소만 입력했을 때 | `entry/vercel.json` `redirects` | `/`로 들어오면 **가장 최신 연도**로 이동. 새 최신 연도를 공개할 때만 바꿈 |
| 연도별 주소 넘겨주기 | `entry/vercel.json` `rewrites` | `/YYYY…`를 그 연도 프로젝트로. 연도마다 4줄, `new-year.py`가 넣어 줌 |
| 없는 주소 안내 화면 | `entry/404.html`, `common/not-found.tsx` | 어느 연도에도 없는 주소(`/zzz`)는 입구의 404.html, 연도 안의 없는 주소(`/2026/zzz`)는 not-found.tsx. 둘은 같은 모양(기본 글꼴·흑백) + 최신 전시·아카이브 링크 |
| 가장 바깥 틀 | `common/layout.tsx` | 언어(한국어), 링크 미리보기 주소 기준(학교 도메인), 기본 제목. 바탕색·글꼴 등은 **넣지 않음** |
| 화면 튕김 방지 | `common/_common/common.css` | 휴대폰에서 맨 위·아래 바운스 끔(카카오톡 덜컹거림 방지) |
| 이미지 저장 방지 | `common/_common/common.css`, `CopyGuard.tsx` | 이미지·영상 우클릭/끌기/길게 눌러 저장 막기, 배포 사이트에서 개발자 도구 단축키 막기 |
| 방문자 기록 | `common/_common/Analytics.tsx` | Google Analytics 4. 배포 사이트에서만 모든 연도 방문을 기록(월·주·일·시간대별, 페이지별). 측정 ID는 이 파일의 `GA_ID`. 운영자 기기는 주소 끝 `?notrack=1`로 한 번 들어가면 그 브라우저에서 기록 안 됨(`?notrack=0` 해제) |
| 파일 주소 구분 | 각 연도 `next.config.ts`의 `assetPrefix: "/YYYY-static"` | 연도 앱들의 JS·CSS 파일 주소가 겹치지 않게. 시작 틀에 들어 있음, 지우지 말 것 |
| 검색에 보일 진짜 주소 | 각 연도 `next.config.ts`의 `headers()` (canonical) | 연도 앱은 `khid-grad-YYYY.vercel.app`으로도 열리지만, 모든 페이지에 "진짜 주소는 `khid.grad.khu.ac.kr/…`" 표시를 붙여 검색에는 학교 도메인만 나오게. 시작 틀에 들어 있음, 지우지 말 것 |
| 새 연도 시작 틀·도구 | `templates/new-year/`, `scripts/` | 아래 "새 연도 추가", "폰트 경량화", "보안 업데이트" |
| 보안 업데이트 | `scripts/update-all.sh`, `.github/dependabot.yml` | 보안 문제가 생기면 **지난 연도까지 모든 연도**를 올림 (아래 "보안 업데이트") |

#### 공통 부품은 연도마다 복사본으로 들어감
연도 앱은 Vercel 프로젝트가 따로라 자기 폴더 밖의 파일을 쓸 수 없습니다. 그래서 `common/`의 파일은 각 연도의 `src/app/`에 **복사본**으로 들어갑니다(`layout.tsx`, `not-found.tsx`, `_common/`). 복사본 맨 위에 "자동 복사본" 표시가 있습니다.

- 공통 부품을 고칠 때: `common/`에서 고친 뒤
  ```bash
  python3 scripts/sync-common.py
  ```
  → 모든 연도 복사본이 바뀝니다. 그다음 연도마다 빌드해서 확인하고 커밋하면 모든 연도가 다시 배포됩니다.
- 복사본을 직접 고치지 마세요. `check-year.py`가 원본과 다른 복사본을 찾아 줍니다.

공통 규칙을 바꾸거나 새로 추가할 때는 이 표도 같이 고치세요. 표에 없으면 공통이 아닙니다.

### 연도별 (절대 섞지 않음)

연도 `YYYY`의 모든 것은 `YYYY/` 폴더(= Vercel 프로젝트 `khid-grad-YYYY`)에만 있습니다. 다른 연도 폴더의 파일을 불러오거나(import) 고치지 않습니다.

| 폴더 | 들어 있는 것 |
|---|---|
| `YYYY/src/app/YYYY/` | 그 연도 페이지 전부, 화면 부품(`_components/`), 데이터(디자이너·작품·졸준위) |
| `YYYY/src/app/YYYY/layout.tsx` | 폰트, 링크 미리보기(카톡·인스타 썸네일), 그 연도 스타일 불러오기 |
| `YYYY/src/app/YYYY/YYYY.css` | 색, 바탕색, 글자 크기 규칙, 애니메이션 등 스타일 전부 |
| `YYYY/src/app/YYYY/icon*.ico·svg`, `apple-icon.png` | 파비콘(브라우저 탭 아이콘)·홈 화면 아이콘 |
| `YYYY/public/YYYY/` | 그 연도 이미지·영상·폰트(`fonts/`) |
| `YYYY/fonts-src/` | 그 연도 폰트 원본 |
| `YYYY/scripts/` | 그 연도에만 쓰는 도구 (예: 2026 프로필 사진 자르기 규칙) |
| `YYYY/package.json`, `next.config.ts` | 그 연도 프로그램 버전·설정 |

- **주소가 `/YYYY/...`로 시작하는 이유**: 연도 앱 안에서도 페이지는 `src/app/YYYY/`, 파일은 `public/YYYY/` 아래에 둡니다. 그래서 입구가 `/2026…` 주소를 그대로 넘겨주면 됩니다.
- **스타일이 섞이지 않는 이유**: `YYYY.css`는 그 연도 페이지에서만 불러오고, Tailwind도 그 연도 폴더 안의 코드만 읽도록 맨 위에 `@import "tailwindcss" source(none); @source "./";`를 둡니다. 새 연도 css에도 꼭 이 두 줄을 넣으세요(Tailwind를 쓰는 경우).
- **연도 사이를 오가는 링크**는 `<Link>` 대신 일반 `<a>`로 거세요. 다른 연도는 다른 앱이라 `<Link>`로는 열리지 않습니다.

### 새 연도 추가 (예: 2027)

**이전 연도 폴더(2026 등)를 통째로 복사하지 않습니다.** 그 해의 공개 날짜·색·설정이 모르는 사이에 따라오기 때문입니다. 대신 빈 시작 틀에서 시작합니다.

1. 시작 틀로 새 연도 앱을 만듭니다. `2027/` 폴더가 생기고, 공통 부품 복사·입구 연결(`entry/vercel.json`)·보안 알림 등록(`.github/dependabot.yml`)까지 자동으로 됩니다.
   ```bash
   python3 scripts/new-year.py 2027
   cd 2027 && npm install next@latest eslint-config-next@latest react@latest react-dom@latest && npm install
   ```
2. `2027/src/app/2027/README.md`의 체크리스트를 채웁니다. **색·폰트·바탕색·파비콘·미리보기 이미지 같은 시각 요소는 전부 새로 정합니다.** 이전 연도 값을 가져오지 않습니다.
3. 이전 연도의 기능(커밍순 공개 게이트, 지도 등)이 필요하면 [FEATURES.md](FEATURES.md)를 보고, **그 기능을 그때 것 그대로 쓸지, 무엇을 바꿀지 확인한 뒤** 하나씩 복사해 옵니다. 디자이너 ↔ 작품 연결은 시작 틀에 기본으로 들어 있습니다.
4. Vercel에서 새 프로젝트를 만듭니다: **Add New → Project → 이 GitHub 저장소 선택 → 이름 `khid-grad-2027`, Root Directory `2027`** → Deploy. 이름이 정확해야 입구가 찾아갑니다(`khid-grad-2027.vercel.app`).
5. 점검합니다. 남은 "[정하기]", 이전 연도 숫자, 빠진 파비콘, 입구 연결 등을 찾아 줍니다.
   ```bash
   python3 scripts/check-year.py 2027
   ```
6. 커밋·푸시하면 입구와 2027 프로젝트가 배포되어 `khid.grad.khu.ac.kr/2027`이 열립니다.
7. 공개할 때 `entry/vercel.json`의 `redirects`에서 `/` 이동을 `/2027`로 바꿉니다.
8. 이전 연도 폴더는 지우지도, 고치지도 않습니다.
9. 아카이브 사이트(저장소 `khuid/khid-archive-site`)에 2027 자료를 추가합니다. 아카이브의 VISIT 링크는 `khid.grad.khu.ac.kr/2027`로 자동 연결됩니다.

- **입구에 연결해 배포하는 순간 `/2027` 주소는 누구나 열 수 있습니다.** 시작 틀은 검색에만 안 나오게 막아 둡니다. 공개 전 화면을 가리려면 커밍순 공개 게이트를 가져오세요.
- **지난 연도(예: 2025)를 나중에 추가**할 때는 7번(최신 연도 이동)만 하지 않습니다.
- 도메인은 입구 프로젝트에 붙어 있으므로 새 연도를 만들 때 학교에 따로 요청할 필요가 없습니다.

### 보안 업데이트

연도마다 프로그램(Next.js 등)이 따로 설치돼 있고, 지난 연도 사이트도 계속 공개돼 있습니다. 그래서 **보안 문제가 생기면 모든 연도를 함께 올립니다.**

- 알림: GitHub이 보안 문제를 발견하면 저장소의 Security 탭과 메일로 알려 주고, 고치는 PR을 만들어 줍니다(`.github/dependabot.yml`에 연도 폴더가 모두 적혀 있어야 함).
- 반영: PR을 하나씩 합치기보다 아래 도구로 모든 연도를 한 번에 올리고 빌드까지 확인하는 걸 권장합니다.
  ```bash
  bash scripts/update-all.sh            # 알려진 보안 문제만 고침
  bash scripts/update-all.sh 16.4.3     # 보안 공지가 Next.js 버전을 알려 줄 때
  ```
  빌드가 실패한 연도가 있으면 알려 줍니다. 바뀐 연도의 화면을 확인한 뒤 커밋·푸시하세요.

### 2026에서 한 방식 (참고)

다음 해에도 비슷하게 하면 편한 것들입니다. 그대로 따를 필요는 없습니다.

- **데이터 위치**: 디자이너 `2026/src/app/2026/_components/designers.ts`, 작품 `projects.ts`(수업별 `WORKS` = 제목·팀원·소개글, `FILES` = 이미지·영상 순서, `LINKS` = 링크), 졸준위 `committee.tsx`.
- **구글폼 → 사이트**: `2026/scripts/import-works.py`가 응답 시트(csv)의 팀원 이름 집합이 **정확히 같은** 작품에 제목·소개글을 원문 그대로 넣고, `import-media.py`가 업로드 파일을 웹용으로 바꿔 `public/2026/projects/<수업>/<작품>/`에 넣습니다(썸네일 가로 1080 webp, 이미지 가로 1920 webp, 영상 H.264 소리 없음). 규격에서 벗어나면 고치지 않고 알려 주므로 사용자에게 확인합니다.
- **반영 원칙**: 소개글은 시트 원문 그대로(400자 초과면 사용자에게 확인), 같은 작품을 다시 내면 마지막 응답 기준, 응답 시트의 메모("썸네일만 재제출" 등)는 그대로 처리하고 사용자에게 알림. 업로드 원본은 저장소 밖에 두고, 바꾼 원본은 지우지 않고 따로 보관.
- **프로필 사진**: `2026/scripts/profile-photos.py`, `tone-match.py`로 같은 구도·톤으로 일괄 처리.
- **Next.js `cacheComponents`**: 서버에서 파일을 읽을 때 비동기 `readFile`을 쓰면 "요청마다 바뀌는 데이터"로 취급돼 정적 페이지가 되지 않습니다(빌드 실패). `readFileSync`를 쓰거나 `"use cache"`로 감쌉니다. 공개 후에는 모든 페이지가 정적(`x-vercel-cache: PRERENDER`)인지 확인합니다.
- **부하**: 2026 공개 전 측정 — 페이지 한 번 그리는 데 약 5ms, 메인 첫 방문 약 1.3MB(폰트 0.7MB 포함). 짧은 시간에 한 컴퓨터에서 요청을 몰아 보내면 Vercel 자동 방어가 그 IP에 보안 확인을 겁니다(일반 브라우저는 자동 통과). 부하 테스트는 로컬 프로덕션 빌드(`next build && next start`)로 합니다.
- **함수 지역**: 연도 앱 `vercel.json`에 `"regions": ["icn1"]`(서울). 시작 틀에 들어 있음(빼면 Vercel 기본값인 미국 동부 iad1이 되어 한국 방문자가 느려짐). 2024·2025는 아직 기본값
