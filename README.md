# KHID 연도별 졸업전시 사이트

`khid.grad.khu.ac.kr` — 주소는 하나지만 `/2026`, `/2027`처럼 경로로 연도를 나눕니다.
**각 연도는 서로 다른 사이트입니다.** 디자인·작품·졸전자·기획·인터랙션이 매년 달라지므로, 한 연도를 고쳐도 다른 연도에는 아무 영향이 없어야 합니다.
(역대 포스터를 모아 둔 전체 아카이브 사이트 `khid.exhibit.khu.ac.kr`는 별도 프로젝트 `archive-site`)

그래서 **연도마다 앱(Vercel 프로젝트)이 따로**이고, 학교 도메인은 작은 **입구**가 받아서 연도별로 넘겨줍니다.

```
방문자 → khid.grad.khu.ac.kr ─ 입구(entry/, Vercel 프로젝트 khid-grad)
                                ├ /            → 가장 최신 연도로 이동
                                ├ /2026…       → 2026 앱(2026/, Vercel 프로젝트 khid-grad-2026)
                                ├ /2027…       → 2027 앱(2027/, Vercel 프로젝트 khid-grad-2027)
                                └ 그 밖의 주소   → 없는 주소 안내(entry/404.html)
```

한 연도를 고쳐 푸시하면 **그 연도 프로젝트만** 다시 배포됩니다(다른 연도는 그대로). 연도마다 프로그램 버전도 따로입니다.

## 저장소 모양

| 폴더 | 들어 있는 것 |
|---|---|
| `README.md`, `CLAUDE.md`, `FEATURES.md` | 공통 규칙(이 문서), Claude용 작업 규칙, 이전 연도 기능 목록 |
| `common/` | 모든 연도가 쓰는 공통 부품 원본 (아래 "공통 규칙") |
| `entry/` | 입구 프로젝트 — 주소 나누기와 없는 주소 안내만 ([entry/README.md](entry/README.md)) |
| `templates/new-year/` | 새 연도 빈 시작 틀 |
| `scripts/` | 공통 도구 (새 연도 만들기, 점검, 공통 부품 복사, 폰트 경량화, 전체 연도 보안 업데이트) |
| `2026/`, `2027/` … | 그 연도 사이트 전부 (코드·데이터·이미지·폰트·그 해 도구) |

이 사이트의 모든 것은 아래 둘 중 하나입니다.

- **공통 규칙**: 매년 똑같이 적용되는 것. 이 문서에 적힌 것만 공통이고, 바꾸면 **모든 연도가 같이 바뀝니다.**
- **연도별**: 그 밖의 전부. 각 연도 폴더 안에만 두고, 다른 연도와 절대 공유하지 않습니다.

> 이전 연도에서 만든 기능 목록은 [FEATURES.md](FEATURES.md)에 있습니다. 공통 규칙이 아니라, 필요할 때 확인하고 가져다 쓰는 기록입니다.
>
> 이 목록에 없는 것은 공통이 아닙니다. "작년에 이렇게 했으니 올해도 그렇겠지" 하고 가져다 쓰지 말고, 필요하면 그 연도 폴더 안에 새로 만드세요.

## 공통 규칙 (모든 연도)

| 무엇 | 어디 | 내용 |
|---|---|---|
| 주소만 입력했을 때 | `entry/vercel.json` `redirects` | `/`로 들어오면 **가장 최신 연도**로 이동. 새 최신 연도를 공개할 때만 바꿈 |
| 연도별 주소 넘겨주기 | `entry/vercel.json` `rewrites` | `/YYYY…`를 그 연도 프로젝트로. 연도마다 4줄, `new-year.py`가 넣어 줌 |
| 없는 주소 안내 화면 | `entry/404.html`, `common/not-found.tsx` | 어느 연도에도 없는 주소(`/zzz`)는 입구의 404.html, 연도 안의 없는 주소(`/2026/zzz`)는 not-found.tsx. 둘은 같은 모양(기본 글꼴·흑백) + 최신 전시·아카이브 링크 |
| 가장 바깥 틀 | `common/layout.tsx` | 언어(한국어), 링크 미리보기 주소 기준(학교 도메인), 기본 제목. 바탕색·글꼴 등은 **넣지 않음** |
| 화면 튕김 방지 | `common/_common/common.css` | 휴대폰에서 맨 위·아래 바운스 끔(카카오톡 덜컹거림 방지) |
| 이미지 저장 방지 | `common/_common/common.css`, `CopyGuard.tsx` | 이미지·영상 우클릭/끌기/길게 눌러 저장 막기, 배포 사이트에서 개발자 도구 단축키 막기 |
| 방문자 기록 | `common/_common/Analytics.tsx` | Google Analytics 4. 배포 사이트에서만 모든 연도 방문을 기록(월·주·일·시간대별, 페이지별). 측정 ID는 이 파일의 `GA_ID`. 운영자 기기는 주소 끝 `?notrack=1`로 한 번 들어가면 그 브라우저에서 기록 안 됨(`?notrack=0` 해제) |
| 파일 주소 구분 | 각 연도 `next.config.ts`의 `assetPrefix: "/YYYY-static"` | 연도 앱들의 JS·CSS 파일 주소가 겹치지 않게. 시작 틀에 들어 있음, 지우지 말 것 |
| 새 연도 시작 틀·도구 | `templates/new-year/`, `scripts/` | 아래 "새 연도 추가", "폰트 경량화", "보안 업데이트" |
| 보안 업데이트 | `scripts/update-all.sh`, `.github/dependabot.yml` | 보안 문제가 생기면 **지난 연도까지 모든 연도**를 올림 (아래 "보안 업데이트") |

### 공통 부품은 연도마다 복사본으로 들어감
연도 앱은 Vercel 프로젝트가 따로라 자기 폴더 밖의 파일을 쓸 수 없습니다. 그래서 `common/`의 파일은 각 연도의 `src/app/`에 **복사본**으로 들어갑니다(`layout.tsx`, `not-found.tsx`, `_common/`). 복사본 맨 위에 "자동 복사본" 표시가 있습니다.

- 공통 부품을 고칠 때: `common/`에서 고친 뒤
  ```bash
  python3 scripts/sync-common.py
  ```
  → 모든 연도 복사본이 바뀝니다. 그다음 연도마다 빌드해서 확인하고 커밋하면 모든 연도가 다시 배포됩니다.
- 복사본을 직접 고치지 마세요. `check-year.py`가 원본과 다른 복사본을 찾아 줍니다.

공통 규칙을 바꾸거나 새로 추가할 때는 이 표도 같이 고치세요. 표에 없으면 공통이 아닙니다.

## 연도별 (절대 섞지 않음)

연도 `YYYY`의 모든 것은 `YYYY/` 폴더(= Vercel 프로젝트 `khid-grad-YYYY`)에만 있습니다. 다른 연도 폴더의 파일을 불러오거나(import) 고치지 않습니다.

| 폴더 | 들어 있는 것 |
|---|---|
| `YYYY/src/app/YYYY/` | 그 연도 페이지 전부, 화면 부품(`_components/`), 데이터(디자이너·작품·졸준위), 공개 전 커밍순 설정 |
| `YYYY/src/app/YYYY/layout.tsx` | 폰트, 링크 미리보기(카톡·인스타 썸네일), 그 연도 스타일 불러오기 |
| `YYYY/src/app/YYYY/YYYY.css` | 색, 바탕색, 글자 크기 규칙, 애니메이션 등 스타일 전부 |
| `YYYY/src/app/YYYY/icon*.ico·svg`, `apple-icon.png` | 파비콘(브라우저 탭 아이콘)·홈 화면 아이콘 |
| `YYYY/public/YYYY/` | 그 연도 이미지·영상·폰트(`fonts/`) |
| `YYYY/fonts-src/` | 그 연도 폰트 원본 |
| `YYYY/scripts/` | 그 연도에만 쓰는 도구 (예: 2026 프로필 사진 자르기 규칙) |
| `YYYY/package.json`, `next.config.ts` | 그 연도 프로그램 버전·설정 |

- **주소가 `/YYYY/...`로 시작하는 이유**: 연도 앱 안에서도 페이지는 `src/app/YYYY/`, 파일은 `public/YYYY/` 아래에 둡니다. 그래서 입구가 `/2026…` 주소를 그대로 넘겨주면 됩니다.
- **스타일이 섞이지 않는 이유**: `YYYY.css`는 그 연도 페이지에서만 불러오고, Tailwind도 그 연도 폴더 안의 코드만 읽도록 맨 위에 `@import "tailwindcss" source(none); @source "./";`를 둡니다. 새 연도 css에도 꼭 이 두 줄을 넣으세요(Tailwind를 쓰는 경우).
- **연도 사이를 오가는 링크**는 `<Link>` 대신 일반 `<a>`로 거세요. 다른 연도는 다른 앱이라 `<Link>`로는 열리지 않습니다.

## 새 연도 추가 (예: 2027)

**이전 연도 폴더(2026 등)를 통째로 복사하지 않습니다.** 그 해의 공개 날짜·색·설정이 모르는 사이에 따라오기 때문입니다. 대신 빈 시작 틀에서 시작합니다.

1. 시작 틀로 새 연도 앱을 만듭니다. `2027/` 폴더가 생기고, 공통 부품 복사·입구 연결(`entry/vercel.json`)·보안 알림 등록(`.github/dependabot.yml`)까지 자동으로 됩니다.
   ```bash
   python3 scripts/new-year.py 2027
   cd 2027 && npm install next@latest eslint-config-next@latest react@latest react-dom@latest && npm install
   ```
2. `2027/src/app/2027/README.md`의 체크리스트를 채웁니다. **색·폰트·바탕색·파비콘·미리보기 이미지 같은 시각 요소는 전부 새로 정합니다.** 이전 연도 값을 가져오지 않습니다.
3. 이전 연도의 기능(커밍순 공개 게이트, 지도 등)이 필요하면 [FEATURES.md](FEATURES.md)를 보고, **그 기능을 그때 것 그대로 쓸지, 무엇을 바꿀지 확인한 뒤** 하나씩 복사해 옵니다. 디자이너 ↔ 작품 연결은 시작 틀에 기본으로 들어 있습니다.
4. Vercel에서 새 프로젝트를 만듭니다: **Add New → Project → 이 GitHub 저장소 선택 → 이름 `khid-grad-2027`, Root Directory `2027`** → Deploy. 이름이 정확해야 입구가 찾아갑니다(`khid-grad-2027.vercel.app`).
5. 점검합니다. 남은 "[정하기]", 이전 연도 숫자, 빠진 파비콘, 입구 연결 등을 찾아 줍니다.
   ```bash
   python3 scripts/check-year.py 2027
   ```
6. 커밋·푸시하면 입구와 2027 프로젝트가 배포되어 `khid.grad.khu.ac.kr/2027`이 열립니다.
7. 공개할 때 `entry/vercel.json`의 `redirects`에서 `/` 이동을 `/2027`로 바꿉니다.
8. 이전 연도 폴더는 지우지도, 고치지도 않습니다.
9. 아카이브 사이트(`archive-site`)의 2027 정보에 링크(`https://khid.grad.khu.ac.kr/2027`)를 넣습니다.

- **입구에 연결해 배포하는 순간 `/2027` 주소는 누구나 열 수 있습니다.** 시작 틀은 검색에만 안 나오게 막아 둡니다. 공개 전 화면을 가리려면 커밍순 공개 게이트를 가져오세요.
- **지난 연도(예: 2025)를 나중에 추가**할 때는 7번(최신 연도 이동)만 하지 않습니다.
- 도메인은 입구 프로젝트에 붙어 있으므로 새 연도를 만들 때 학교에 따로 요청할 필요가 없습니다.

## 보안 업데이트

연도마다 프로그램(Next.js 등)이 따로 설치돼 있고, 지난 연도 사이트도 계속 공개돼 있습니다. 그래서 **보안 문제가 생기면 모든 연도를 함께 올립니다.**

- 알림: GitHub이 보안 문제를 발견하면 저장소의 Security 탭과 메일로 알려 주고, 고치는 PR을 만들어 줍니다(`.github/dependabot.yml`에 연도 폴더가 모두 적혀 있어야 함).
- 반영: PR을 하나씩 합치기보다 아래 도구로 모든 연도를 한 번에 올리고 빌드까지 확인하는 걸 권장합니다.
  ```bash
  bash scripts/update-all.sh            # 알려진 보안 문제만 고침
  bash scripts/update-all.sh 16.4.3     # 보안 공지가 Next.js 버전을 알려 줄 때
  ```
  빌드가 실패한 연도가 있으면 알려 줍니다. 바뀐 연도의 화면을 확인한 뒤 커밋·푸시하세요.
- 커밋 작성자는 Vercel 팀 멤버 계정이어야 배포됩니다(Hobby 요금제 제한). GitHub 봇이 만든 PR을 그대로 합치면 배포가 막힐 수 있어 위 도구를 권장합니다.

## 폰트 경량화

한글 폰트는 원본이 커서 실제로 쓰는 글자만 남긴 경량본을 씁니다. 연도마다 폰트가 다를 수 있어서 연도별로 따로 만듭니다.
원본은 `YYYY/fonts-src/`(.woff2·.ttf·.otf), 경량본은 `YYYY/public/YYYY/fonts/`에 둡니다. 경량본에는 기본 한글 2,350자와 그 연도 소스에 실제로 들어간 글자(이름·작품명 등)가 들어갑니다.
데이터를 **다 넣은 뒤** 한 번 실행하세요. 다른 연도 폰트는 건드리지 않습니다.
```bash
pip install fonttools brotli   # 처음 한 번
python3 scripts/subset-fonts.py 2026
```

## 배포 구성 (Vercel, 팀 `khid`)

| Vercel 프로젝트 | Root Directory | 주소 |
|---|---|---|
| `khid-grad` (입구) | `entry` | `khid.grad.khu.ac.kr` (학교 도메인은 여기에 연결) |
| `khid-grad-2026` | `2026` | `khid-grad-2026.vercel.app` (입구가 `/2026…`을 넘겨줌) |

- 각 폴더의 `vercel.json`에 "지난 배포 이후 그 폴더가 안 바뀌었으면 빌드 건너뛰기"(`ignoreCommand`)가 있어서 한 연도를 고치면 그 연도만 배포됩니다.
- 학교 도메인 DNS는 Vercel을 가리키고 있어서, 같은 Vercel 팀 안에서 도메인을 다른 프로젝트로 옮겨도 학교에 다시 요청할 필요가 없습니다. 다른 Vercel 계정·팀으로 옮길 때만 다시 요청합니다.
